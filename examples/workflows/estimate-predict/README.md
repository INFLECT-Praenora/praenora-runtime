# Example workflow: estimate and predict

`workflow.yaml` configures the catalog's workflow definition `example.estimate-predict@0.1.0`
with the two example modules of this repository, over the observations in
`data/observations.csv`. It runs 12 ticks of one day each (`time: {unit: d, start: 0.0,
period: 1.0}`), with the run seed 20261110.

```
inputs.observations --> [estimate] --state--> [predict] --predictions--> outputs.predictions
                           ^  prior (optional)    |
                           +----- delay 1 --------+                estimate.state --> outputs.state
```

- **estimate** (`example-estimator`, `examples/modules/estimator`): for each series and variable,
  it blends each usable observation `y` with the previous tick's prediction `p` at the
  observation's time, `p + gain * (y - p)` (basis `blend`), or takes the observation itself when
  there is no prediction there (basis `observation`). A series without a usable observation in
  the tick carries the prediction at the window's end over (basis `prior`). The feedback
  connection is delayed by one tick, so tick 0 has no predictions and only observations.
- **predict** (`example-predictor`, `examples/modules/predictor`): from each estimate it
  integrates the logistic equation `dx/dt = r x (1 - x / K)` with the classical Runge-Kutta
  method (fixed step `step_size`, the last step before each output time shortened to land on it)
  and predicts the `latent_mean` every `output_interval` from the tick's end to `horizon` later.

Both modules are deterministic and use only `+ - * /` arithmetic. Each comes with test vectors
(`vectors.json`, one case of two ticks taken from a run of this workflow), which the build copies
next to its manifest.

`workflow-python.yaml` is the same configuration with the predict step bound to
`example-predictor-python` (`examples/modules/predictor-python`), the predictor as a Python module:
the same parameters, outputs and test vectors, computed with numpy, every estimate's numbers going
through the C++ predictor's operations in the same order. Its outputs are those of
`workflow.yaml`, byte for byte, but for the start of each message's `id`, which names the run. It
needs the runtime's provider `python`, which a build with `PRAENORA_WITH_PYTHON_ENVIRONMENT=ON`
holds, and builds the module
([module-developer-guide.md](../../../docs/module-developer-guide.md#modules-in-python)).

## Running it

The configuration names no module search path: whoever runs it names the directory of the built
example modules, `build/<preset>/modules` (`build/<preset>/modules/<config>` with a
multi-configuration generator). From C++:

```cpp
#include <praenora/runtime/runtime.hpp>

praenora::RuntimeOptions options;
options.module_paths = {"build/dev/modules"};
const praenora::Runtime runtime(options);

praenora::WorkflowOptions run;
run.output_dir = "runs/estimate-predict"; // outputs/, run-record.json
const auto workflow = runtime.open("examples/workflows/estimate-predict/workflow.yaml", run);
const praenora::RunSummary summary = workflow->run();
```

With the Python predictor, from a build with the Python environment (the local preset
`dev-python`), in module hosts, as Python steps are best run (macOS and Linux):

```bash
./build/dev-python/bin/praenora run examples/workflows/estimate-predict/workflow-python.yaml \
    --module-path build/dev-python/modules --output-dir "${TMPDIR:-/tmp}/estimate-predict-python" \
    --isolation process
```

The integration tests (`ctest --preset dev -L integration`) run it end to end and compare its
outputs with the golden files in `tests/fixtures/golden/example.estimate-predict/`, and, with the
Python environment, those of `workflow-python.yaml` with those of `workflow.yaml`. The golden
files are refreshed only on request, after checking that every tick from 1 on has a blend and that
every value is finite and positive:

```bash
PRAENORA_UPDATE_GOLDEN=1 ctest --preset dev -R '^Example\.OutputsMatchGolden'
```

## The data

`data/observations.csv` holds two series of the variable `population` (unit `count`) at
irregular times within the 12 days: S01 follows the logistic curve with x0 = 10, r = 0.30 and
K = 100, S02 the one with x0 = 25, r = 0.25 and K = 80, and every value carries a small
deterministic perturbation. One row is missing and one is left-censored; the estimator skips both.

The file is generated by a deterministic script that needs only the Python standard library. To
regenerate it, from the repository root:

```bash
python3 tools/generate_example_data.py > examples/workflows/estimate-predict/data/observations.csv
```
